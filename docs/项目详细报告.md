## 一、项目概述

### 1.1 项目定位

小洛实验室（XiaoLuo Lab）是一个**本地优先、可服务器部署**的智能数据科学实验平台，目标是将「数据处理 → 数据探索 → 智能合并 → 机器建模 → Agent 智能分析 → 工作流编排 → 实验报告」整合到同一套体系。项目代号 `xiaoluo-lab`，面向**高校毕业设计、数据科学实验教学、本地化数据分析与建模**三大场景。

### 1.2 设计原则

项目自始至终贯彻以下六条原则，构成了系统的"骨架约束"，也是理解其架构的钥匙：

| 原则 | 含义 | 落地体现 |
| --- | --- | --- |
| 本地优先 | 数据与实验产物存本地文件系统与本地数据库 | `storage/local.py` + SQLite |
| 可服务器部署 | 提供 Docker 化部署，支持多用户 | `docker-compose.yml` + 前后端 Dockerfile |
| 面向教学 | 覆盖完整链路，支持中文实验报告自动生成 | `reports/*` 三格式导出 |
| AI 编排 | 内置 Agent 系统（Context→Planner→Permission→Executor→Validator→Replanner） | `app/agent/*` |
| 可复现 | 数据操作产生不可变版本快照，实验绑定版本 + 随机种子 | `DatasetVersion` 不可变 + `seed` |
| 安全可控 | 无 shell/eval/exec 通道，工具走注册表，存储防路径穿越 | `storage/security.py` + `TOOL_REGISTRY` |

### 1.3 技术栈总览

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript 5 + Vite 5 + Zustand + React Router 6 + axios + recharts | 路由懒加载、SSE 流式、9 类图表渲染 |
| 后端 | FastAPI + Python 3.12 + Pydantic v2 + SQLAlchemy 2 + Alembic | 统一 `/api/v1` 前缀、12 个 Router |
| 数据引擎 | Polars（Lazy Execution）+ PyArrow（列式零拷贝） | `pl.DataFrame` 是领域层通用数据协议 |

| LLM | OpenAI Compatible（httpx 直连，不绑定厂商） | 支持 DeepSeek 等任意兼容 API |

## 二、整体架构设计

### 2.1 系统分层

项目采用**前后端分离**的单体分层架构，后端内部再按"接入层 → 依赖装配 → 服务层 → 领域能力层 → 数据访问/基础设施层"五层组织。

```
┌──────────────────────────────────────────────────────────────┐
│  接入层  app/main.py → app/api/v1/*（12 个 router）           │  HTTP/SSE、参数校验、响应包装
└───────────────┬──────────────────────────────────────────────┘
                │  Depends
┌───────────────▼──────────────────────────────────────────────┐
│  依赖装配  app/api/deps.py                                    │  进程级单例：AGENT_STORE、WORKFLOW_SERVICE
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│  服务层（领域门面）                                            │
│  services/dataset_service · file_service                      │
│  data_engine/service.py（DataEngineService）                  │
│  experiments/service.py（ExperimentService）                  │
│  workflow/service.py（WorkflowService）                       │
│  agent/runtime/*（AgentRuntime）                              │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│  领域能力层                                                    │
│  analysis.py（质量/画像/EDA/可视化）· ml_engine/*             │
│  data_engine/{loaders,operations,merge,merge_multi}           │
│  reports/*（生成/叙述/导出）· tools/*（Agent 工具集）         │
│  workflow/{executor,runners,validator,state}                  │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│  数据访问 / 基础设施                                           │
│  models/*（SQLAlchemy）· core/database.py（Session）          │
│  storage/*（对象存储抽象）· core/{config,logging,middleware}   │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 分层约定的遵守情况

| 约定 | 现状 |
| --- | --- |
| 路由层不写业务逻辑 | ✅ 基本遵守（路由只做参数校验 + 调 service + 包装 `ApiResponse`） |
| 领域层不依赖 FastAPI | ✅ `data_engine`/`ml_engine`/`analysis` 均无 FastAPI 导入 |
| 依赖方向自上而下 | ⚠️ 存在一处倒置：`analysis.py` 依赖 `data_engine/{exceptions,json_utils}`，而 `data_engine/service.py` 又依赖 `analysis`，形成双向依赖 |
| 异常统一 | ✅ `core/exceptions.py` 定义 8 类业务异常，由 ASGI 中间件统一兜底 |

### 2.3 核心架构特征

**（1）不可变版本快照模型（贯穿全系统的核心不变量）**

数据修改一律产生**新版本**（新行 + 新 parquet 文件），原版本永不覆盖。这一不变式是：
- 数据可复现的基础；
- 实验可复现的基础（实验绑定 `DatasetVersion` 而非 `Dataset`）；
- 版本级 DataFrame 缓存"永不失效"的理论依据。

**（2）进程级单例与单 worker 约束**

`AGENT_STORE`、`WORKFLOW_SERVICE`、`_RESERVED_SESSIONS` 均为进程内状态。这意味着**当前架构隐含要求单 worker**——若用 `uvicorn --workers > 1`，Agent SSE/confirm 与 Workflow run/cancel 会出现"请求落到另一个进程"的失效。这是当前架构最重要的一个部署约束。

**（3）工具注册表 + 权限管理的安全边界**

Agent 无任何 shell/eval/exec 通道，所有工具调用强制经 `TOOL_REGISTRY.execute`，且每次执行前经 `PermissionManager.check` 裁决（ALLOW / DENY / REQUIRE_CONFIRMATION）。这是"AI 编排安全可控"原则的核心实现。

## 四、关键功能与技术实现

### 4.1 数据处理与版本化

- **上传与加载**：`POST /files/upload` 上传原始文件，`POST /datasets/upload` 直接创建数据集（产生 v1 快照）。支持 CSV/Excel/JSON/Parquet，由 `data_engine/loaders.py` 的 `REGISTRY` 按扩展名匹配加载器。
- **9 类操作**：missing/duplicate/cast/string/filter/transform/aggregate/pivot/melt，经 `OPERATION_REGISTRY` 调度，新增操作只需注册无需 if/else。
- **安全过滤 DSL**：filter 操作使用白名单算子（eq/neq/gt/gte/lt/lte/contains/in/is_null）+ and/or 逻辑，**禁止 eval/exec**。

### 4.2 智能合并（计划-预览-校验-执行四段分离）

合并严格遵循四段分离，且 preview 与 execute 必须使用同一对版本号，防止错位：

```
POST /merge/mapping → POST /merge/keys → POST /merge/preview
→ POST /merge/validate → POST /merge/execute
```

- **字段映射建议**：`schema_mapper.suggest_mappings` 比较字段名/类型/样本值/唯一性/缺失率，输出带 confidence 的 `MappingCandidate`。
- **Join Key 分析**：`key_analyzer.analyze_join_keys` 支持单 Key 与 **composite key**（多列组合键按元组分析）。
- **执行校验**：`MergeExecutor.execute` 强制"先校验后执行"，冲突列自动唯一命名。

### 4.3 探索性分析（EDA）

EDA 实现已合并到 `app/analysis.py`（与 Profiling/Quality 同模块），只读不产生新版本：

| 分析器 | 端点 | 说明 |
| --- | --- | --- |
| `DescriptiveAnalyzer` | `/eda/descriptive` | 描述性统计 |
| `DistributionAnalyzer` | `/eda/distribution` | 分布分析（直方图/KDE/分箱） |
| `CorrelationAnalyzer` | `/eda/correlation` | 相关性矩阵（Pearson/Spearman/auto） |
| `EdaOutlierAnalyzer` | `/eda/outlier` | 异常值检测（IQR/Z-score） |

**9 类图表**（`VisualizationBuilder`）：histogram / bar / line / scatter / boxplot / heatmap / **qq**（自研 Acklam 逼近，零 scipy 依赖）/ **grouped_bar** / **area**（CDF）。其中后三类达到科研级。

### 4.4 机器学习

- **11 个内置模型**：4 分类（逻辑回归/KNN/决策树/随机森林）+ 4 回归 + 2 聚类（KMeans/DBSCAN）+ 1 PCA，统一 `ModelAdapter` 接口。
- **任务自动识别**：`ml.detect_task` 根据目标列类型、基数、缺失率推断 classification/regression/clustering。
- **防数据泄漏**：`PreprocessingPipeline` 基于 sklearn `ColumnTransformer` + `Pipeline`，统计量只在 fit 阶段计算。
- **可复现**：seed → `random_state` 注入 + 分层切分，测试锁定同 seed 指标一致。
- **训练前 preflight**：校验 target 存在/非空、分类至少 2 类、回归样本足够，非法直接抛业务异常。

### 4.5 Agent 系统（AI 编排核心）

Agent 链路：

```
User Request
  → ContextBuilder.build（绝不发送完整数据集，最多 5 行采样）
  → AgentPlanner.build_plan（LLM 或规则规划，受 max_steps 限制）
  → AgentExecutor.execute_step → TOOL_REGISTRY.execute
  → PermissionManager.check（ALLOW / DENY / REQUIRE_CONFIRMATION）
  → Tool.execute → ToolResult
  → AgentResultValidator.validate（NaN/Inf 检查、Schema 必需字段）
  → 失败时 Replanner.replan（重试一次→跳过该步；硬限制防无限循环）
  → AgentRun.final_answer（LLM 总结或确定性拼接）
```

- **22 个内置工具**：dataset（6）/ data（5）/ eda（5）/ ml（6），按类别组织。
- **对话/工具路由**：`_route` 基于问候语与数据任务关键词分流；会话绑定数据集时兜底进入工具流程。
- **死循环防线**（三重保护）：尝试数写回 + 重试不前进下标 + 每次迭代过熔断；另有 `MAX_EVENTS_PER_RUN=2000` 硬护栏。
- **SSE 流式**：`stream=true` 时起 daemon 线程跑 runtime，事件经 queue 推流；高风险步骤停在 WAITING_CONFIRMATION 时 SSE 保持打开并持续 tail 事件，用户确认后 resume 继续。

### 4.6 工作流（DAG 引擎）

- **节点与边**：`Workflow` 由 `Node`（type + config）+ `Edge`（source/target）组成。
- **内置节点类型白名单**：noop / data.load / data.clean / data.duplicate / data.cast / data.string / data.filter / data.transform / data.aggregate / data.pivot / data.melt。
- **执行语义**：拓扑排序（Kahn 算法）后逐节点执行；节点失败 → FAILED，后继 SKIPPED，其它分支继续；支持取消。

### 4.7 实验与报告

- **实验结构**：`Experiment` 绑定 dataset_id + dataset_version_id（不可变快照）+ task + model + parameters + preprocessing + seed。
- **报告生成**：`ReportGenerator.generate` 接收 EDA/ML/Quality/Experiment 结构化输入，组织为中文实验报告（数据概览/数据质量/探索性分析/建模评估/结论），支持 Markdown/HTML/PDF 三格式导出，PDF 中文字体可配置。
- **LLM 叙述**：`narrator.narrate_report` 基于真实工具结果撰写报告章节正文，含事实摘要截断与完整性校验。

**代码质量整体处于中上水平**，领域层分层清晰、异常体系完整、安全设计到位、测试覆盖充分（509 用例）。主要短板集中在**性能与规模化**（数据加载与缓存策略）和**部署约束显式化**（单 worker 约束、鉴权缺失）两个维度。

各模块完成度：

| 数据处理 | 高 | 操作注册表设计优雅，版本快照不变式贯彻彻底 |
| 智能合并 | 高 | 四段分离 + composite key + 版本固定，工程严谨 |

### 5.2 代码质量亮点

1. **分层清晰、依赖方向基本自上而下**：`data_engine`/`ml_engine`/`analysis` 均无 FastAPI 导入，领域层可独立测试。
2. **异常体系完整**：8 类业务异常 + ASGI 中间件统一兜底，业务异常与系统异常分离。
3. **安全设计到位**：路径穿越防护、Prompt 注入防御、无 eval/exec、API Key 脱敏、响应头注入防护。
4. **边界处理细致**：常数列、单样本 std、NaN/Inf、空 df、分母为 0、空 Parquet 全有兜底。
5. **可复现性贯穿**：版本快照不可变 + seed 注入 + 分层切分，实验可复现。
6. **工程细节考究**：相对路径 DB URL 按 `BACKEND_ROOT` 锚定、env 文件锚定、`extra="ignore"` 容错。

## 六、优化建议

### 6.1 短期（P0/P1，低风险高收益）

1. **补最小鉴权**：先给"改全局凭据"类接口加可选管理员令牌，再逐步把写接口纳入统一鉴权依赖。
2. **明确单 worker 约束**：在启动脚本/部署文档固定 `uvicorn --workers 1`，加显式注释。
3. **AgentStore 持久化换实现**：迁移到 SQLite（ORM 已具备），或按 run 分文件 + 增量追加。
4. **抽公共层解双向依赖**：`app/common/{errors,json_utils}`，顺带消灭 3 份 `json_safe` 重复。
5. **全量预测导出**：`predict(write_back=True)` 将预测列落库为新数据集版本。
6. **补齐体积/超时上限**：上传大小限制 + 训练采样上限 + 分析软超时接线。

### 6.2 中期（P2，重构减负）

7. **合并重复实现**：JSON 安全化 1 份、截断策略 1 份、`_FENCE_RE` 1 份、直方图分桶 1 份、`_make_estimator` 基类默认实现、抽 `DatasetService.load` 消灭 13 处两段式。
8. **清理死代码**：按清单逐项删除（每项独立提交便于回滚）。
9. **依赖声明补齐**：显式声明 `numpy`；引入 `deptry`/`ruff --select F401` 进 CI。

### 6.3 中长期（功能扩展，毕设可讲）

10. **交叉验证 + 置信区间**：单次切分指标波动大，加 K 折 CV 与置信区间。
11. **模型注册/版本化、再训练与漂移检测**。
12. **分析结果持久化与历史对比**：新增 `AnalysisRun` 表，回答"清洗后质量变好了吗"。
13. **异步训练 + 进度轮询**：`run.status` 状态机已具备，把执行移出请求线程。
14. **交叉表/列联表分析 + 相关性 p 值**：补 EDA 常见缺口。
